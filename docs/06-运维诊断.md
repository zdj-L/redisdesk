# 06 · 运维诊断

> 文档集版本 v2.0（企业级安全） ｜ 2026-11-10 ｜ 参数见 [02 附件 A.4](./02-架构与技术选型.md) ｜ 风险联动见 [05 §2](./05-命令控制台.md)、[08 §3 身份与授权](./08-安全与风险清单.md)

诊断页目标：不改数据、不阻塞服务端，用最少命令拿到排障所需信息。**除 `CLIENT KILL`、`SLOWLOG RESET` 与批量删除（均走控制台风险流程）外，本页全部只读。**

角色约束概览：

| 能力 | Viewer | Operator | Admin |
| --- | --- | --- | --- |
| 概览 / 慢查询 / 客户端列表 / 内存分析 / 分节 INFO | ✓ | ✓ | ✓ |
| 大 key 扫描（P3） | ✗ | △ 只读采样，可取消 | ✓ |
| 批量按模式删除 | ✗ | ✗ | △ 预估 + 限流 + 二次确认 |
| `CLIENT KILL` | ✗ | ✗ | △ 单条 + 展示目标 |
| 慢查询/诊断结果导出 | ✗ | △ 默认脱敏 | △ 去脱敏需二次口令 + 理由 |
| 审计导出 | ✗ | ✗ | ✓ |

```
诊断
├─ 概览       INFO 关键指标 + 健康判定
├─ 慢查询      SLOWLOG GET
├─ 客户端      CLIENT LIST
├─ 内存        MEMORY STATS / DOCTOR / USAGE（含批量估算、大 key 扫描）
└─ 分节 INFO   server / clients / memory / persistence / stats / replication / keyspace
```

## 1. 概览与健康判定

### 1.1 数据来源

| 指标卡 | 来源 | 刷新 |
| --- | --- | --- |
| 版本 / 运行时长 | `INFO server`（`redis_version`/`uptime_in_seconds`） | 手动（`info_auto_refresh_s=0`） |
| 内存使用 / 上限 | `INFO memory`（`used_memory_human`/`maxmemory_human`） | 手动 |
| 连接数 | `INFO clients`（`connected_clients`/`blocked_clients`） | 手动 |
| 命中率 | `INFO stats`（`keyspace_hits`/`keyspace_misses`） | 手动 |
| 淘汰 / 拒绝 | `INFO stats`（`evicted_keys`/`rejected_connections`） | 手动 |
| 复制状态 | `INFO replication`（`role`/`master_link_status`/`connected_slaves`） | 手动 |
| 持久化 | `INFO persistence`（`rdb_last_bgsave_status`/`aof_last_bgrewrite_status`） | 手动 |
| Key 数量 | `INFO keyspace`（逐 db 的 `keys`/`expires`/`avg_ttl`） | 手动 |

- 一次 `INFO`（不带分节）即可拿到以上全部信息，避免 8 次往返；页面上仍按分节展示。
- 自动刷新默认关闭；用户可选 5/10/30 秒（`info_auto_refresh_s`），开启时顶栏显示"每 5s 刷新"。

### 1.2 健康判定阈值

| 指标 | 正常 | 警告（黄） | 严重（红） | 说明 |
| --- | --- | --- | --- | --- |
| `used_memory / maxmemory` | < 80% | 80%~90% | > 90% 或 `maxmemory=0` 且 > 8 GB | `maxmemory=0` 表示未设上限，单独提示 |
| `mem_fragmentation_ratio` | 0.9~1.5 | 1.5~2.0 | > 2.0 | < 1 说明发生 swap，标红 |
| `evicted_keys`（自启动累计） | 0 | > 0 | 持续增长 | 有淘汰说明内存压力大 |
| `rejected_connections` | 0 | > 0 | 持续增长 | 连接数超 `maxclients` |
| `blocked_clients` | 0 | 1~10 | > 10 | 有阻塞命令（`BLPOP` 等） |
| `keyspace_hits / (hits+misses)` | ≥ 95% | 90%~95% | < 90% | 分母为 0 时显示"无读写" |
| `master_link_status`（本节点为从） | `up` | — | `down` | 从节点复制中断 |
| `rdb_last_bgsave_status` / `aof_last_bgrewrite_status` | `ok` | — | `err` | 持久化失败 |
| `connected_slaves`（本节点为主） | ≥ 1（若有从） | 低于期望 | 0 且配置要求有从 | 期望值由用户在连接备注中自定义，默认不判 |

每条异常都给出**可执行建议**（例如"淘汰增长：检查 `maxmemory-policy`，见 `CONFIG GET maxmemory-policy`"），并在建议旁提供"复制命令到控制台"按钮（只填入不执行）。

### 1.3 分节 INFO 展示

| 分节 | 展示方式 | 特别处理 |
| --- | --- | --- |
| `server` | 键值表（键名可搜索） | 隐藏/脱敏不存在敏感项 |
| `clients` | 键值表 | — |
| `memory` | 键值表 + 使用率进度条 | `used_memory_rss` 与 `used_memory` 并列 |
| `persistence` | 键值表 | 失败状态标红 |
| `stats` | 键值表；命中率单独计算展示 | `commandstats` 大表默认折叠 |
| `replication` | 主节点/从节点卡片 | 从节点逐行展示 `ip/port/state/offset/lag` |
| `cpu` | 键值表 | — |
| `commandstats` | 表格：命令 / calls / usec / usec_per_call | 默认按 `usec` 降序取前 10，可展开全部 |
| `cluster` | 键值表（集群模式） | `cluster_enabled:1` 时显示槽覆盖是否完整 |
| `keyspace` | 表格：db / keys / expires / avg_ttl | 集群下逐节点展示 |

原始 `INFO` 全文提供"查看原文"抽屉，便于对照版本差异。

## 2. 慢查询日志

| 项 | 设计 |
| --- | --- |
| 拉取 | `SLOWLOG GET slowlog_count=128`（可调 32~512）；`SLOWLOG LEN` 显示总条数 |
| 展示 | 默认表格显示 `slowlog_display_rows=50` 条，按耗时降序；可切换"按时间倒序" |
| 列 | `id`、发生时间（`timestamp` 转本地时间）、`duration_us`（同时显示 ms）、`命令`（`argv[0]`）、`参数摘要`（脱敏后前 200 字符）、`客户端地址`、`客户端名` |
| 详情 | 抽屉显示完整 `argv`（脱敏），提供复制 |
| 前置检查 | 顶部读取 `CONFIG GET slowlog-log-slower-than slowlog-max-len`：为 `-1` 时提示"慢查询未开启（阈值为 -1）"，为 0 时提示"记录所有命令，开销较大" |
| 敏感处理 | `argv` 中 `AUTH`/`CONFIG SET requirepass` 等按 05 §6 规则脱敏后再展示与导出；命令参数中命中敏感 key 规则的部分按 04 §2.1 遮罩 |
| 导出 | 慢查询导出 CSV 仅 Admin/Operator；默认脱敏，去脱敏需 Admin + 二次口令 + 理由 ≥10 字符，审计 `event=export_unmasked` |
| 写操作 | `SLOWLOG RESET` 不在本页提供按钮；需要时走控制台（L2 确认），避免误清诊断证据 |

性能：`SLOWLOG GET 128` 返回最多 128 条，响应通常 < 10 ms；超时按 `socket_timeout_s=5` 处理。

## 3. 客户端列表与 KILL

### 3.1 展示

`CLIENT LIST` 一次拉取，解析为表格：

| 列 | 字段 | 说明 |
| --- | --- | --- |
| ID | `id` | KILL 目标标识 |
| 地址 | `addr` | `ip:port` |
| 名称 | `name` | 业务通过 `CLIENT SETNAME` 设置 |
| 库 | `db` | cluster 下为 0 |
| 空闲 | `idle` | 秒 |
| 标志 | `flags` | `N` 普通、`M` 主、`S` 从、`O` 仅订阅等 |
| 订阅 | `sub`/`psub` | 订阅数 |
| 队列 | `qbuf`/`qbuf-free` | 输入缓冲 |
| 输出 | `obl`/`oll`/`omem` | 输出缓冲与内存（`omem` 大是异常信号） |
| 最近命令 | `cmd` | 便于定位"谁在打什么" |

- 行数上限 `client_list_display_max=2000`，超出提示"客户端过多，已截断，建议用筛选"。
- 筛选：按名称/地址/命令/标志；排序：按 `idle`、`omem`、`qbuf` 降序。
- 异常标记：`omem > 10 MB` 或 `qbuf > 1 MB` 或 `idle > 3600` 的行加黄色徽标（仅提示，不自动处理）。

### 3.2 KILL 流程（L3）

```
选中行 → 点击"断开该客户端"
  ├─ 确认框展示：ID、地址、名称、当前命令、空闲时长
  ├─ 提示：该客户端可能属其它业务/同事，断开可能导致其请求失败
  ├─ 输入连接名确认 → 发送 CLIENT KILL ID <id>
  └─ 结果：1 = 已断开；0 = 客户端已不在（提示刷新）
```

| 约束 | 内容 |
| --- | --- |
| 角色 | **仅 Admin**；Operator/Viewer 无入口，即便通过快捷键触发也在 `AuthzService` 被拒（`deny_reason=role`） |
| 禁止批量 KILL | 不提供多选 KILL；一次一个 |
| 自我保护 | 若目标 `addr` 与本连接一致（`CLIENT INFO` 取自身 `addr`），拒绝并提示"不能断开当前连接" |
| 只读档 | 拒绝（L3） |
| 审计 | `decision=allow, command=CLIENT KILL` 记录目标 ID（不含敏感信息） |
| 替代方案 | 优先建议业务方自行重连或排查；KILL 是最后手段 |

## 4. 内存分析

### 4.1 服务端整体

| 命令 | 展示 |
| --- | --- |
| `MEMORY STATS` | 键值表：`peak.allocated`、`total.allocated`、`startup.allocated`、`dataset.bytes`、`overhead.total`、`keys.count`、`keys.bytes-per-key`、`dataset.percentage`、`peak.percentage`、`fragmentation` |
| `MEMORY DOCTOR` | 原文展示（Redis 自带诊断建议），空字符串表示"无问题" |
| `INFO memory` | 与 §1 一致，避免重复请求 |

`MEMORY STATS` 在超大实例上有一定开销（遍历统计），只允许手动触发，并提示"可能耗时数十毫秒"。

### 4.2 单 key 精确占用

| 项 | 设计 |
| --- | --- |
| 命令 | `MEMORY USAGE key SAMPLES 0`（`memory_usage_samples_single=0`，精确） |
| 入口 | 值查看器面板"内存占用"按钮 + 诊断页"单 key 查询"输入框 |
| 展示 | 字节数（人类可读）+ 采样说明"精确（全采样）"+ 耗时 |
| 大 key | 单 key > 100 MB 时先提示"精确统计可能耗时数百毫秒" |

### 4.3 批量估算（P2）

| 项 | 设计 |
| --- | --- |
| 输入 | 名称模式 + 类型 + 数量上限（默认 2000，最大 10000） |
| 命令 | `SCAN COUNT 500` 取样 + pipeline `MEMORY USAGE key SAMPLES 5`，`memory_usage_batch_keys=200` 一批 |
| 输出 | 表格（key/类型/估算字节/元素数）+ 汇总（总计、Top 20）；**所有数值标注"估算（SAMPLES 5）"** |
| 成本 | 1000 key ≈ 2 次 `SCAN` + 5 次 pipeline；10000 key ≈ 20 + 50 次；提示"会给服务端带来额外 CPU" |
| 限制 | 只读；不提供"按大小排序全库" |

### 4.4 大 key 扫描（P3 可选，Q8 已定：采样版）

| 项 | 设计 |
| --- | --- |
| 目的 | 在**不阻塞**前提下给出"疑似大 key Top N"，不追求精确全量 |
| 采样 | `SCAN COUNT 1000`，最多 `bigkey_scan_sample_max=50000` 个 key；每个 key `MEMORY USAGE SAMPLES 5`（200 一批） |
| 判定 | 超过 `big_string_bytes=10 MB` 或 `big_collection_items=10,000`（用 `STRLEN/HLEN/LLEN/SCARD/ZCARD/XLEN` 取元素数，避免只依赖内存估算） |
| 输出 | Top 50 表格：key、类型、元素数、估算内存、建议（如"按业务拆分/改 hash tag/设置 TTL"） |
| 时间成本 | 5 万 key ≈ 50 次 `SCAN` + 250 次 pipeline 往返；同机房 1~3 秒，跨网 10 秒+；可暂停/取消 |
| 精度成本 | `SAMPLES 5` 是估算，实际可能偏差 ±20%；UI 必须写明"估算值" |
| 覆盖范围 | 只覆盖采样窗口内的 key；`MATCH` 前缀可提高相关性（但会减少覆盖） |
| 生产开关 | 默认关闭；开启时提示"这是采样扫描，会持续 1~10 秒，建议低峰执行" |
| 集群 | 逐 master 采样，结果按节点分组；总采样上限按节点均分（50000 / 节点数） |
| 授权 | 需会话 + 角色（Operator 起）+ 连接授权；`viewer` 无入口 |
| 遮罩 | 结果中的 key 名按 [04 §2.1](./04-Key浏览与值查看器.md) 规则遮罩；导出默认脱敏 |

**明确不做**：全库逐 key 精确 `MEMORY USAGE SAMPLES 0` 扫描（100 万 key 会产生 100 万次命令，属于事故级操作）。

## 5. 批量按模式删除（P2）

仅在 `env != prod`、保护档位非 `readonly`、且当前角色为 **Admin** 时提供入口；生产连接不显示该功能。

```
输入模式 user:tmp:* → 预估（SCAN 500 抽样/全量计数）→ 确认 → 执行
```

| 步骤 | 细节 |
| --- | --- |
| 1 预估 | `SCAN MATCH <pattern> COUNT 500` 最多扫描 `scan_budget_cursor_steps` 或 30 秒，得到"匹配 key 数（至少 N，可能更多）"；不承诺精确总数 |
| 2 确认 | 弹框显示：模式、预估数量、目标连接、环境；要求**输入连接名** + 勾选"我确认这些 key 可删除"；单次上限 `batch_delete_max_keys=500` |
| 3 执行 | 重新 `SCAN`（避免过期结果），`UNLINK`（不支持时 `DEL`），`delete_pipeline_batch=100` 一批，批间 `delete_pause_ms=20` |
| 4 限流 | 每批后检查取消；总删除量达 `batch_delete_total_max=10000` 停止并提示"已删除 10000 个，达到单次上限" |
| 5 二次确认 | 每删满 500 个，弹出"已删除 500 个，继续下一批？"，可勾选"本任务内不再询问"（仅 dev/test 可用） |
| 6 结果 | 成功/失败计数、耗时、失败原因前 20 条；写入审计（`command=UNLINK(batch)`，含模式摘要而非全部 key、预估/实际数量、角色、理由）；预估与执行各一条独立记录 |
| 禁止 | 生产连接、`readonly` 档、非 Admin 角色、模式为 `*`（空模式需显式输入 `*` 并额外确认，且仅 dev） |

## 6. 只读约束与性能边界

| 操作 | 复杂度 | 阻塞风险 | 本工具约束 |
| --- | --- | --- | --- |
| `INFO` | O(1)~O(命令数) | 低 | 手动刷新，自动刷新 ≥ 5 s |
| `SLOWLOG GET 128` | O(128) | 低 | 上限 512 |
| `CLIENT LIST` | O(客户端数) | 低 | 上限 2000 行展示 |
| `MEMORY STATS` | O(键空间统计) | 中 | 手动触发，提示耗时 |
| `MEMORY USAGE SAMPLES 0` | O(key 大小) | 中（大 key） | 仅单 key，> 100 MB 先提示 |
| `MEMORY USAGE SAMPLES 5` 批量 | O(采样数 × key 数) | 中 | 200/批、上限 10000 key |
| 大 key 扫描 | O(采样 key 数) | 中 | 上限 50000 key，可取消 |
| 批量删除 | O(删除量) | 高（写） | 限流 + 上限 10000 + 非生产 + 仅 Admin |
| `CLIENT KILL` | O(1) | 低（但影响他人） | L3 单条确认 + 仅 Admin |
| 审计导出 | O(行数) | 无 | 仅 Admin；默认脱敏；单次 ≤ 20 万行 |

## 7. 验收要点

| 编号 | 用例 | 通过标准 |
| --- | --- | --- |
| V1 | 打开诊断概览 | 单次 `INFO` 获得全部卡片；无自动刷新时不会持续请求 |
| V2 | `maxmemory` 使用 92% | 卡片标红并给出建议；建议可一键填入控制台 |
| V3 | 慢查询阈值 `-1` | 顶部提示"未开启"，表格为空且不报错 |
| V4 | 慢查询命令含 `AUTH` | 参数显示 `***`，复制内容同样脱敏 |
| V5 | 客户端列表 3000 条 | 展示 2000 条并提示截断；筛选后仍可用 |
| V6 | KILL 当前连接自身 | 拒绝并提示"不能断开当前连接" |
| V7 | 批量删除 1200 个 key | 每 500 个二次确认；限流生效；总耗时可见；审计有记录 |
| V8 | 大 key 扫描 5 万 key | 1~3 秒（同机房）内完成或可取消；结果标注"估算" |
| V9 | 集群诊断 | `INFO cluster` 与逐节点 `INFO memory` 均可展示；不误用单机 `DBSIZE` |
| V10 | 生产连接打开诊断页 | 看不到批量删除与 `MONITOR` 入口 |
| V11 | `operator` 打开诊断页 | 慢查询/客户端/内存可用；批量删除、`CLIENT KILL`、审计导出入口不可见 |
| V12 | 慢查询命令含敏感 key（`GET token:abc`） | 参数摘要中 key 名遮罩；导出 CSV 同样遮罩 |
| V13 | 大 key 扫描结果含 `session:*` | key 名列遮罩；汇总统计不受影响 |
| V14 | 审计库设为只读后执行 `CLIENT KILL` | 返回 E13，未发送命令；审计不可写期间只读诊断仍可用 |
