## 1. 阶段划分

| 阶段 | 目标 | 一句话验收 |
| --- | --- | --- |
| **P0** 可用 | 单机直连下"能看、能查、能安全地执行"，且具备最小可信身份与审计 | 100 万 key 浏览不卡、`KEYS` 零调用、未登录不可操作、审计链可校验 |
| **P1** 覆盖 | 覆盖真实运维环境（SSH/Sentinel/Cluster）与完整诊断 | 三种拓扑 + SSH 均可连接并浏览；慢查询/客户端/INFO 可用 |
| **P2** 效率 | 把高频但高成本的操作做成"受控批处理" | 批量删除限流可审计、大小/TTL 过滤可用、审计可导出 |
| **P3** 可选 | 增值能力，默认关闭 | 大 key 采样、压缩解包、RESP3 等按开关启用 |

不做时间估算；阶段之间按"退出条件"推进，未满足不进入下一阶段。

> v2.0 的变化：**身份、角色、审计哈希链、强制 TLS、敏感遮罩从"P2 增强"前移到 P0**。理由：这些是"事后无法补救"的能力——没有审计链就无法证明操作归属，后补等于历史数据不可信。

### 7.2 原始选项与理由（决策背景）

#### Q1 生产连接的默认保护档位？

| 选项 | 内容 |
| --- | --- |
| **A（推荐）** | `env=prod` 强制 `readonly`，只能查看与只读命令；要写入需新建 `env=test` 连接 |
| B | `confirm` + 强制输入连接名，允许在生产写 |
| C | 仅顶部警告，不改变能力 |

**推荐 A**：排查工具 95% 的使用是只读；生产写入应该走有变更流程的通道（控制台或专用连接），把"写"变成需要额外动作的事，能挡住绝大多数手滑。代价是"临时改个 TTL"也要另建连接，但可通过"从生产连接克隆为测试连接"降低摩擦。

#### Q2 是否提供值编辑（写回 String/Hash）？

| 选项 | 内容 |
| --- | --- |
| **A（推荐）** | 不做。所有写操作只走命令控制台 |
| B | P3 仅支持 String 编辑（带乐观校验 `WATCH`） |
| C | P2 支持全类型编辑 |

**推荐 A**：值编辑器要处理并发覆盖、类型冲突、大 value 截断写回、二进制误改，工程成本高且事故率高；排查场景用 `SET` 一条命令即可完成。若确有编辑需求，再按 B 单点开放 String。

#### Q3 Cluster 浏览的默认行为？

| 选项 | 内容 |
| --- | --- |
| **A（推荐）** | 默认扫描全部 master（并发 2），列表带节点/槽列，进度按节点展示 |
| B | 默认只扫当前选中节点，用户手动切换节点 |
| C | 默认单节点，且不提供全集群扫描 |

**推荐 A**：运维最常问"这个 key 在哪个节点/全集群有没有这个前缀"，逐节点手动切换体验差；A 的成本可控（每节点一条游标、并发 2、可暂停）。B 可作为"只看某节点"的筛选器保留，但不做默认。

#### Q4 `FLUSHALL/FLUSHDB/SHUTDOWN` 在生产连接如何处理？

| 选项 | 内容 |
| --- | --- |
| **A（推荐）** | `SHUTDOWN`/`DEBUG`/订阅阻塞命令永久阻断；`FLUSHALL/FLUSHDB` 在 `env=prod` 永久阻断，仅 dev/test 可解锁 |
| B | 允许在 prod 通过输入连接名解锁 |
| C | 全部只做二次确认，不区分环境 |

**推荐 A**：清库与停机在生产上几乎不可能是"正确的临时操作"，一旦发生就是事故；把它们从工具能力里拿掉，不会影响正常排障（清测试数据用测试连接）。B 的"解锁"在紧急情况下反而容易被误用。

#### Q5 压缩解包与图片预览放在哪个阶段？

| 选项 | 内容 |
| --- | --- |
| **A（推荐）** | P3，默认关闭、仅手动、上限 10 MB |
| B | P2 提供 gzip/zstd 自动识别按钮 |
| C | 不做 |

**推荐 A**：这两项是"看着方便、出事很贵"的能力（解压炸弹、超大图片卡 UI）；先保证核心浏览与安全，再作为可选开关。若团队缓存里大量 gzip 数据，可提前到 P2。

#### Q6 审计保留期与导出格式？

| 选项 | 内容 |
| --- | --- |
| **A（推荐）** | 保留 180 天 + CSV 导出（UTF-8 BOM，Excel 可直接打开） |
| B | 保留 365 天 |
| C | 保留 90 天 + JSONL 导出（便于日志平台采集） |

**推荐 A**：180 天覆盖大多数"季度复盘/事后追溯"窗口；CSV 对运维最友好。若公司合规要求更长，改 `audit_retention_days` 即可，但需注意本地库增长（20 万行上限会滚动删除）。若已有日志平台，追加 JSONL 可作为 P2 小增量。

#### Q7 是否需要英文界面？

| 选项 | 内容 |
| --- | --- |
| **A（推荐）** | 仅中文 |
| B | 中英双语（i18n 框架 + 两套文案） |

**推荐 A**：目标用户为中文团队，术语（`SCAN`/`slot`/`TTL`）本身保留英文；引入 i18n 会显著增加文案维护与布局适配成本，收益低。若未来有外籍同事，再补 i18n。

#### Q8 大 key 扫描是否进入交付范围？

| 选项 | 内容 |
| --- | --- |
| **A（推荐）** | P3 可选模块：采样 5 万 key、`SAMPLES 5`、Top 50、可取消 |
| B | P2 就做，且扩大采样到 20 万 |
| C | 不做，仅保留单 key `MEMORY USAGE` |

**推荐 A**：大 key 排查是真实需求，但精确扫描在百万/千万实例上成本不可控；采样版能在 1~3 秒给出参考结论，符合"排查工具"定位。B 的 20 万采样在跨网环境会到分钟级，容易变成"点了就后悔"的功能。

### 7.3 新增待决（Q9~Q13，安全升级引入）

| 编号 | 问题 | 默认行为（未拍板前按此实施） | 推荐 |
| --- | --- | --- | --- |
| Q9 | 未授权连接"可见不可连"还是"完全隐藏"？ | 可见但灰色 + "未授权"徽标；Admin 可开 `hide_unauthorized_connections` | **A：保持可见**（资产盘点需要，避免重复建连）；隐藏作为可选项 |

| Q13 | 主密码（`dpapi_master`）是否强制用于所有连接？ | 不强制，连接级可选；默认 `dpapi` | **A：不强制**；高敏连接由 Admin 指定 |
