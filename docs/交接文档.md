## 1. 项目是什么

**一句话**：给开发和运维用的 Windows 桌面 Redis 客户端，聚焦"看缓存、查问题、做轻量运维"，并把生产误操作与数据泄漏作为首要防范对象。

| 项 | 事实 |
| --- | --- |
| 当前阶段 | **只有设计文档，没有任何功能代码** |
| 代码状态 | `<project-root>` 下 `build/`、`redisdesk/`、`scripts/`、`tests/` 均为**空目录**；`docs/` 之外**零文件** |
| 能否直接运行 | **不能**。没有 `pyproject.toml`、没有入口文件、没有依赖锁定文件 |
| 交付形态（设计） | Windows 单机 exe，Python 3.11 + PySide6 + Nuitka 打包，无服务端、无云端 |
| 与 dbsync 的关系 | 同机 `<reference-project dbsync>` 是**已存在的另一个工具**，本项目只借鉴其技术栈与 UI 设计系统；**独立项目、独立目录、不共享代码**；**任何情况下不得修改 dbsync 的文件**（只读参考） |
| 文档版本 | 全部 10 篇已升级到 v2.0（企业级安全），日期统一 2026-11-10 |

接手前必须建立的预期：现在拿到的是"设计已评审、代码未开始"的状态。任何"跑一下看看"的尝试都会失败，这是正常的。

## 3. 技术选型与理由

| 选型 | 版本锁定 | 理由 | 风险/备注 |
| --- | --- | --- | --- |
| Python | ≥ 3.11 | 与 dbsync 一致；`tomllib`、`ExceptionGroup`、更快的启动 | 打包后不暴露解释器 |
| PySide6 | 6.8.2.1（**仅 QtWidgets**） | Qt 授权 LGPL 可商用；dbsync 已验证同版本 | 不用 QML/QtQuick，避免额外运行时与体积 |
| redis-py | 5.2.1 | 支持 RESP2/RESP3、Cluster、Sentinel、连接池 | 不用 `KEYS`/`HGETALL` 等封装；只保留原语调用 |
| paramiko | 3.5.1 | 纯 Python SSH，便于 Nuitka 打包 | 需自己实现 `host_key_sha256` 固定（见 03 §6） |
| cryptography | ≥ 42 | scrypt / AES-256-GCM / SHA-256，全部由它提供 | 不自己实现密码学 |
| SQLite | Python stdlib | 审计、历史、账号、授权、配置全本地；WAL 并发读 | 单写者由 `Global\RedisDesk` 互斥量保证 |
| Nuitka | 2.4.x | 与 dbsync 一致；编译为原生 exe，启动快、反编译成本高 | 需 MSVC 工具链；签名流程见 08 §8 |
| pytest | 最新稳定 | 单测/集成测试 | UI 用 `pytest-qt`（待定，未锁定） |

**为什么不用 Electron / Tauri / .NET**：dbsync 已在 PySide6 上验证过打包与 UI 体系；换栈会让两个工具的设计系统与打包脚本分裂，维护成本翻倍。

**为什么用 SQLite 而不是 JSON 文件存审计**：需要按时间/连接/角色过滤、需要事务与 WAL、需要行数上限滚动删除；JSON 无法满足，且哈希链需要稳定的追加语义。

## 4. 核心设计决策与原因（不要改回旧方案）

| 编号 | 决策 | 原因 | 错误改法 |
| --- | --- | --- | --- |
| D1 | 连接 = **拓扑（direct/sentinel/cluster）× 传输（tcp/ssh）** 两个正交维度 | 组合爆炸用枚举会失控；两维可独立演进 | 把"SSH 集群"做成第四种拓扑 |
| D2 | 连接是**中立资源**，不带"源/目标"角色 | 同一连接既可能被查也可能被写；源/目标语义会诱导危险默认值 | 给连接加 `role=source/target` |
| D3 | 浏览**只走 `SCAN`**，代码内禁止 `KEYS`/`HGETALL`/`LRANGE 0 -1`/`SMEMBERS` 全量 | 单线程 Redis 上这些命令会阻塞数秒~数十秒 | "小实例无所谓，加个开关" |
| D4 | 安全默认值优先于开关：`env=prod` 强制只读、L4 永久阻断 | 开关最终都会被关掉；默认值才是真实策略 | 提供"我知道风险，仍然允许"全局开关 |
| D5 | 写命令**禁止自动重试** | 超时不代表未执行，重试会重复写（`INCR`/`LPUSH`） | 复用读路径的重试装饰器 |
| D6 | 集群语义**独立实现**，不做"看起来像单机" | 跨槽、逐节点 `DBSIZE`、`SELECT` 不可用等差异必须暴露 | 用 `RedisCluster` 包一层就宣称支持 |
| D7 | **不做值编辑**，写只走控制台 | 值编辑器会绕过风险分级与二次确认，是误删/误改的主要来源 | 加"小心一点"的编辑框 |
| D8 | 授权与风险判定**只允许**在 `core/authz.py`、`core/policy.py` | 判定散落必然出现旁路（历史回放、快捷键、批量任务） | 在页面里写 `if role == 'admin'` |
| D9 | 审计**只追加**，不 `UPDATE` 原记录 | `UPDATE` 会破坏哈希链，等于自证不可信 | "执行完更新一下结果字段" |
| D10 | 敏感值**默认遮罩**，明文是临时状态 | 有"关闭遮罩"开关等于默认不遮 | 提供全局"显示明文"复选框 |
| D11 | 生产不可写由**数据库 CHECK 约束**兜底 | UI 可能被绕过；约束不会 | 只在 UI 层禁用 |
| D12 | 安装/更新**必须签名**，拒绝降级 | 客户端持有全部凭据，被替换等于凭据全失 | "内网分发不用签名" |

### 5.2 强制项、代价与例外路径（08 §10 全 12 条）

| 强制项 | 可用性代价 | 例外路径 | 留痕 |
| --- | --- | --- | --- |
| 必须登录 | 每次启动多一步 | 无（不可关闭） | `auth_login` |
| 三角色最小权限 | Viewer 不能改 TTL | Admin 提升角色 | `user_change` |
| 生产连接强制只读 | 生产改 TTL 需另建测试连接 | 新建 `env=test` 连接 | `profile_change` |
| L4 永久阻断（`SHUTDOWN/DEBUG/订阅`） | 工具内无法停服/调试 | 用 redis-cli 走堡垒机（工具外） | 不适用 |
| 强制 TLS | 未开 TLS 的自建 Redis 连不上 | Admin 标记"允许明文" + 理由 ≥10 字符 | `high_risk_plaintext` |
| 审计 fail-closed | 磁盘满/库坏时不能写 | 无，必须修存储 | `audit_*` |

| 更新需签名 | 无法自行改包分发 | 无 | `update_verify` |
| SSH 密钥认证优先 | 需配置密钥 | 口令认证 + 中风险标记 | `connect`（含 auth_mode） |

### 5.3 审计哈希链

- 算法：`record_hash = SHA256(canonical_json(record) || prev_hash)`，创世 `prev_hash` 为 64 个 `0`；`audit_hash_algo=SHA-256`（固定，不可改）。
- 字段：`seq`、`prev_hash`、`record_hash`、`actor`、`session_id`、`client_version`、`event`、`command`、`risk_level`、`decision`、`deny_reason`、`result`、`duration_ms`、`created_at`。
- 完整性：启动校验末 500 条；`[校验完整性]` 可全量（上限 20 万行）；断链时进入**只读应急模式**（仅 L1，禁导出、禁改安全参数），6 步处理流程见 08 §7.4。
- fail-closed：审计不可写 → 写命令与 L3/L4 拒绝（E13），只读继续并挂红色横幅（05 §4.3）。

### 5.4 其它要点

| 主题 | 结论 |
| --- | --- |
| TLS | `tls_required` 默认开、`tls_version_min=TLSv1.2`、`verify_hostname` 固定 true；明文例外需 Admin + 理由 + 红色标识 + 审计 |
| SSH | 密钥优先，`host_key_sha256` 固定，**没有"忽略并继续"** |
| 凭据 | `dpapi`（默认）/ `dpapi_master`（主密码）/ `none`（不落盘）；运行时用 `SecretLease` 短期持有 |
| 导出包 | AES-256-GCM（nonce 12 B、tag 16 B）+ scrypt(N=32768, r=8, p=1, dklen=32)；禁止明文导出 |
| Redis 侧 | `acl_probe.py` 检测 `default` 账号可用与高危 ACL；提供 `redisdesk_ro/rw/admin` 三套可执行 ACL（03 §9.2） |
| 闲置锁定 | 空闲 10 分钟 + 绝对 8 小时；联动 Windows 锁屏；切换连接不继承解锁 |

## 7. 实施路径

| 阶段 | 范围 | 退出条件（摘要） | 依赖 |

## 9. 安全边界声明（诚实版）

1. **不是 Redis 网关/代理/堡垒机**：工具直连 Redis，所有流量不经过本工具的服务端（它没有服务端）。
2. **不能替代网络隔离与 Redis ACL**：真正的权限边界在 VPC/安全组/Redis ACL；本工具的角色只是"本机操作约束"。
3. **不防本机管理员**：拥有 Windows 管理员权限的人可以读 DPAPI 密文、改程序、删审计库；本工具只做"提高成本 + 留痕"，不做"防不住也要假装防住"。
4. **不防内存 dump**：明文值在渲染期间存在于进程内存，`SecretLease` 只能缩短生命周期。
5. **审计不是 WORM**：本地 SQLite 可被整体删除；哈希链只能证明"被改过"，不能阻止删除。
6. **不做 MFA / SSO / 集中日志**：本期只有本地账号；企业统一身份是后续扩展点（`IdentityProvider`）。
7. **不保证集群一致性快照**：逐节点 SCAN 看到的是"某一时刻的近似集合"。
8. **不替代服务端审计**：Redis 侧的 `MONITOR`/慢查询/ACL 日志仍需在服务端开启。
