## 1. 四种连接形态

连接是**中立资源**：一条连接只是"某个 Redis 可达端点的访问方式"，没有"源/目标""主/备"之类的角色语义。拓扑与传输是两个正交维度：

```
拓扑 topology：direct（单机或主从端点） / sentinel（哨兵发现） / cluster（集群）
传输 transport：tcp（TLS 强制，明文需例外） / ssh（本地端口转发）
```

| 形态 | topology | transport | 典型场景 | 关键配置 | 交付阶段 |
| --- | --- | --- | --- | --- | --- |
| ① 直连 | `direct` | `tcp` | 内网单机、主从架构的只读端点 | host、port、db、TLS（默认必需） | P0 |
| ② Sentinel | `sentinel` | `tcp` | 主从 + 哨兵，需自动跟随主节点 | master_name、哨兵列表、哨兵 TLS | P1 |
| ③ Cluster | `cluster` | `tcp` | 3 主 3 从及以上集群 | seed 节点列表（全部继承 TLS） | P1 |
| ④ SSH 隧道 | 任意 | `ssh` | 跳板机后的 Redis | SSH 主机、密钥优先、指纹固定 | P1（`direct`/`sentinel`）；P2（`cluster`） |

SSH 是传输层的叠加：`direct+ssh`、`sentinel+ssh` 均合法；`cluster+ssh` 需要为每个 master 单独建隧道，见 §6.4。

**禁止**在 `ConnectionProfile` 中出现 `role`、`source`、`target`、`primary`、`replica` 字段（除非是拓扑探测的运行时结果 `NodeInfo.role`，不落库）。这里的 `role` 指"连接角色"，与本地账号角色 `viewer/operator/admin` 无关。

## 2. 连接配置字段

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `name` | str | 必填 | 显示名，唯一；建议格式 `项目/环境/用途`，如 `订单/生产/只读` |
| `topology` | enum | `direct` | `direct` / `sentinel` / `cluster` |
| `transport` | enum | `tcp` | `tcp` / `ssh` |
| `host` / `port` | str / int | — / `6379` | `direct` 必填；`sentinel`/`cluster` 下作为默认种子（可选） |
| `db` | int | `0` | `direct`/`sentinel` 有效；`cluster` 强制 0 且 UI 置灰 |
| `username` | str | 空 | Redis 6+ ACL 用户名；空 = `default` 用户，连接测试会告警（§9.1） |
| `secret_ref` | str | 空 | 指向 `secret` 表；界面不显示明文 |
| `secret_mode` | enum | `dpapi` | `dpapi` / `dpapi_master` / `not_stored`（见 §7.1） |
| `tls` | object | **启用** | `enabled=true`、`version_min=TLSv1.2`、`ca_path`、`client_cert_path`、`client_key_path`、`verify_hostname=true`（不可关） |
| `allow_plaintext` | bool | `false` | 明文例外开关，仅 Admin 可置真，必须附 `plaintext_reason`（§3.2） |
| `ssh` | object | 关闭 | 见 §6.1 |
| `sentinel` | object | — | `master_name`、`sentinels`（默认端口 26379）、`sentinel_username`、`sentinel_secret_ref`、`sentinel_tls` |
| `cluster` | object | — | `seeds`（≥1 个 host:port）、`slot_cache_ttl_s`（默认 300） |
| `env` | enum | `dev` | `prod` / `test` / `dev`；**决定默认保护档位与 L4 权限** |
| `protection` | enum | 见 §8.1 | `readonly` / `confirm` / `unrestricted` |
| `allow_l4` | bool | `false` | 是否允许 L4；`env=prod` 强制 false；即使为真也需 Admin 角色 |
| `tags` | list[str] | 空 | 本地过滤用 |
| `note` | str | 空 | 备注，例如"仅供排查，勿写入" |

`env` 与 `protection` 的联动：

| `env` | 保存时的 `protection` | 是否允许改为 `unrestricted` | `allow_l4` |
| --- | --- | --- | --- |
| `prod` | **强制 `readonly`** | 否（UI 置灰，服务端再校验） | 强制 `false`，不可改 |
| `test` | `confirm` | 是（需 Admin + 二次确认 + 审计） | 可开启（仍需 Admin 角色执行 L4） |
| `dev` | `confirm` | 是（同上） | 可开启（仍需 Admin 角色） |

> 生产写入的唯一合法路径：**另建一条 `env=test` 的连接**并填写用途说明，写入审计 `profile_change`。不允许把 prod 连接改成可写。

## 3. TLS 强制与明文例外

### 3.1 强制 TLS

| 项 | 约定 |
| --- | --- |
| 默认 | 新建连接必须启用 TLS（等价 `rediss://`），不勾 TLS 无法保存 |
| 协议版本 | `tls_version_min=TLSv1.2`，允许 1.3；禁止 1.0/1.1 |
| 证书校验 | `tls_verify_hostname=true` 固定；校验证书链 + 主机名；**无"忽略证书错误"开关** |
| CA | 自签/私有 CA 必须显式提供 `ca_path`；不隐式信任系统库之外的证书 |
| 客户端证书 | 可选 mTLS：`client_cert_path` + `client_key_path`；私钥口令走 DPAPI；到期 < `tls_cert_expiry_warn_days=30` 告警 |
| 哨兵 | 独立 `sentinel_tls`；哨兵与数据面可不同证书 |
| 集群 | 所有节点继承连接 TLS；不支持单节点降级，某节点握手失败即连接失败 |
| 失败 | 握手失败/主机名不匹配/证书过期 → E01 或 E07，不自动重试、不降级 |
| 证书查看 | 连接详情展示：协议版本、证书主体、签发者、到期时间、SHA-256 指纹 |

实现：`adapters/tls.py` 构建 `ssl.SSLContext(PROTOCOL_TLS_CLIENT)`，显式 `minimum_version=TLSVersion.TLSv1_2`、`check_hostname=True`、`verify_mode=CERT_REQUIRED`、`load_verify_locations(ca_path)`。

### 3.2 明文例外（高风险，需留痕）

| 项 | 约定 |
| --- | --- |
| 触发 | 取消 TLS 时必须勾选"允许明文（不推荐）"并填写 `plaintext_reason`（≥ `plaintext_reason_min_chars=10` 字符） |
| 权限 | 仅 `admin`；`operator`/`viewer` 无此选项（服务端再校验一次） |
| 落库 | `allow_plaintext=1`、`plaintext_reason`、`approved_by`、`approved_at` |
| 标识 | 连接卡片红色左边框 + 红色徽标"明文"；连接后顶栏常驻红色提示"明文连接" |
| 留痕 | 创建/修改时 `event=high_risk_plaintext`（含理由）；每次连接 `event=connect_plaintext`（L3） |
| 复核 | 审计页支持筛选"明文事件"；连接详情显示批准人与理由 |
| 禁止 | 导入包中的明文连接直接拒绝导入；不提供批量转为明文的操作 |

## 4. 直连（`direct` + `tcp`）

`redis.Redis(host, port, db, username, password, ssl_context=ctx, socket_timeout, socket_connect_timeout, health_check_interval, decode_responses=False)`。

要点：

1. **始终 `decode_responses=False`**：值可能是二进制，解码在 `codec.py` 统一处理。
2. 连接池 `max_connections=pool_max_connections(4)`，`retry_on_timeout=False`，不自动重试（02 §6 规则 3）。
3. 建连后执行 `PING` + `INFO server` 获取版本 → `Capabilities`；< 6.0 时类型过滤降级。
4. `db` 校验：以 `CONFIG GET databases` 的 N 为准，允许 0~N-1；越界或 `SELECT` 失败返回 E04；`cluster` 强制 `db=0`。
5. 密码通过 `SecretLease` 注入（§7.3），不进入 `ConnectionProfile`、不进入日志。
6. 连接建立后执行 ACL 自检（§9.1），结果在连接详情与顶栏提示，不阻断连接。

**主从端点差异**：连到 replica 时读正常、写返回 `READONLY You can't write against a read only replica`。`INFO replication role:slave` 时顶栏显示 `只读副本` 徽标，保护档位临时降为 `readonly`（不落库，仅本次会话）。

## 5. Sentinel（`sentinel` + `tcp`）

### 5.1 参数

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `master_name` | 必填 | 如 `mymaster` |
| `sentinels` | 必填，≥1 | `host:port`，未写端口按 `sentinel_port=26379` |
| `sentinel_username` / `sentinel_secret_ref` | 空 | 哨兵开启 `requirepass` 时使用（`secret_mode` 同连接） |
| `sentinel_tls` | 继承连接 TLS | 哨兵 TLS 独立配置，默认同样启用 |
| `require_master_role` | `true` | 取连接前校验 `ROLE` |
| `discover_retry` | `3` | 绑定的 `sentinel_discover_retry` |
| `discover_backoff_ms` | `500` | 发现失败重试间隔 |

### 5.2 发现流程

```
start
  ├─ 依次对每个哨兵 PING（connect_timeout_s=5，哨兵 TLS 握手）
  │    └─ 全部失败 → E06，列出每个哨兵的失败原因
  ├─ SENTINEL get-master-addr-by-name <master_name>
  │    ├─ 返回 nil → 名称错误/未注册 → E06（不重试）
  │    └─ 得到 (master_host, master_port)
  ├─ 用连接自身凭据（SecretLease）建立到主节点的临时连接
  │    ├─ ROLE / INFO replication → role:master ? 继续 : 重新发现（≤3 次）
  │    └─ INFO server → Capabilities；ACL 自检
  ├─ 可选：SENTINEL MASTER <name> 读取 quorum / num-slaves / flags
  └─ 建立 master 连接池（pool_max_connections=4）→ ConnectionWorker
```

### 5.3 故障转移后的行为

| 事件 | 检测 | 行为 | 用户可见 |
| --- | --- | --- | --- |
| 主节点被切走 | `READONLY` 或断连 | 重发现 master、重建池；读命令自动重试 1 次，写命令不重试 | "主节点已切换：新地址 x.x.x.x:6379" |
| 全部哨兵不可达 | 发现阶段 PING 失败 | 保留旧连接（若可用），提示"哨兵不可达，使用缓存地址" | 黄条 + 每次取连接校验角色 |
| 发现结果与缓存不同 | 每次取连接时 | 新池建好后替换，旧池延迟 5 s 关闭 | 状态栏提示 |

Sentinel 模式下**不提供**"手动指定主节点"覆盖：允许覆盖会在故障转移后继续写旧主，造成脑裂式误写。

### 5.4 与直连的差异

| 项 | 直连 | Sentinel |
| --- | --- | --- |
| 端点 | 用户写死 | 每次发现，地址会变 |
| `SELECT db` | 支持 | 支持 |
| 写命令 | 直接可用 | 只保证发往当前 master，切换瞬间可能 `READONLY` |
| 拓扑信息 | 无 | 可展示 `SENTINEL MASTERS`/`SENTINEL REPLICAS`（只读） |
| 键空间 | 单实例 | 单主节点键空间（从节点不参与浏览） |
| TLS | 单一配置 | 哨兵 TLS 与数据面 TLS 分别配置 |

## 6. SSH 隧道（`transport=ssh`）

### 6.1 SSH 参数

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `host` / `port` | — / `22` | 跳板机地址 |
| `username` | 必填 | SSH 账号 |
| `auth_mode` | `key`（推荐默认） | `key` / `password`；口令方式需勾选并标记中风险 |
| `password` / `passphrase` | 空 | 以 `secret` 表加密保存（`kind=ssh_password` / `ssh_key_passphrase`），或 `not_stored` 每次输入 |
| `private_key_path` | 空 | `auth_mode=key` 必填；支持 RSA/Ed25519/ECDSA；只读引用，禁止复制进应用目录 |
| `known_hosts_policy` | `strict` | `strict` 读系统 `known_hosts`；`tofu` 首次确认后写入 `known_hosts_redisdesk` |
| `host_key_sha256` | 首次固定 | 固定指纹；变更即拒绝（§6.3） |
| `password_auth_flagged` | `false` | 口令认证标记，写入审计与连接详情 |
| `local_port` | `0` | 0 = 系统分配；只绑 `127.0.0.1` |

### 6.2 建立流程

```
start
  ├─ SSH 连接（connect_timeout_s=5）
  ├─ host key 校验（strict / tofu + 指纹确认）
  ├─ 认证（私钥 + passphrase 优先；口令认证需已标记）
  ├─ 本地监听 127.0.0.1:<local_port>（0 则随机）
  └─ 入站 TCP → direct-tcpip channel → 远端 Redis（Redis 侧仍走 TLS 校验）
```

### 6.3 约束与指纹固定

| 约束 | 内容 |
| --- | --- |
| 绑定地址 | **只允许 127.0.0.1**，禁止 `0.0.0.0` |
| 指纹固定 | 首次确认后固定 `host_key_sha256`；后续不匹配直接拒绝（E07），**不提供"忽略并继续"按钮**；需人工核对后删除 `known_hosts_redisdesk` 中对应条目重新登记 |
| 认证方式 | 密钥优先；口令认证需标记 `password_auth_flagged=true`，审计记录 `auth_mode=password` |
| 生命周期 | 随连接会话启停；断开即关闭监听端口 |
| 端口占用 | 分配失败 → E07，提示手工指定端口 |
| 保活 | `ssh_keepalive_s=30`；连续 3 次失败视为失效，进入"需重连" |
| 超时叠加 | Redis 侧仍用 `socket_timeout_s=5`；SSH 层不压缩超时 |
| 认证失败 | 区分"跳板机认证失败"与"Redis 认证失败" |

### 6.4 `cluster + ssh` 限制（P2）

| 限制 | 说明 |
| --- | --- |
| 手工映射 | `ssh.node_mappings: [{remote: "10.0.0.11:6379", local: 16379}]`，须覆盖全部 master |
| 不自动推导 | 无法从拓扑自动生成本地端口 |
| 变更需维护 | 扩容/换主后映射失效，报 E05 |
| 默认关闭 | 实验性开关，默认关；开启时顶部黄条提示 |

## 7. 凭据保护

### 7.1 三种存储模式

| 模式 | 默认 | 行为 | 适用 |
| --- | --- | --- | --- |
| `dpapi` | ✓ | DPAPI（当前 Windows 用户 + 应用熵）加密后存本地库 | 日常 |
| `dpapi_master` | 可选 | DPAPI 密文再被主密码派生密钥包裹（scrypt → AES-256-GCM）；启动/解锁需主密码 | 高敏环境、共享电脑 |
| `not_stored` | 可选 | 不落盘，每次连接现输入；仅保留用户名与主机 | 一次性排障 |

| 项 | 约定 |
| --- | --- |
| DPAPI | `CryptProtectData`，scope=当前用户，`CRYPTPROTECT_UI_FORBIDDEN`，熵=`redisdesk:v2:credential` |
| 主密码 | 长度 ≥ `master_password_min_length=12`；scrypt(N=32768,r=8,p=1) 派生 KEK；AES-256-GCM 包裹 DPAPI 密文；失败 `master_password_fail_threshold=5` 次锁定 `master_password_lock_minutes=15` |
| 明文位置 | 仅 `SecretLease` 内的 `bytearray`/`memoryview`，退出即清零；禁止 `str`、repr、异常消息、日志 |
| 换机/换用户 | DPAPI 解密失败 → E02，提示"凭据与 Windows 用户绑定，请重新输入" |
| 删除连接 | 同事务删除 `connection`、`connection_grant` 与 `secret`；启动清理孤儿行 |
| UI | 密码框掩码；"按住显示"不写入剪贴板；无"复制密码" |

### 7.2 存储结构

```sql
CREATE TABLE connection (
    id            TEXT PRIMARY KEY,
    name          TEXT NOT NULL UNIQUE,
    topology      TEXT NOT NULL CHECK (topology IN ('direct','sentinel','cluster')),
    transport     TEXT NOT NULL CHECK (transport IN ('tcp','ssh')),
    host          TEXT,
    port          INTEGER NOT NULL DEFAULT 6379,
    db            INTEGER NOT NULL DEFAULT 0,
    username      TEXT,
    secret_id     TEXT,
    secret_mode   TEXT NOT NULL DEFAULT 'dpapi'
                  CHECK (secret_mode IN ('dpapi','dpapi_master','not_stored')),
    tls_json      TEXT NOT NULL,           -- 含 enabled/version_min/ca_path/verify_hostname
    allow_plaintext INTEGER NOT NULL DEFAULT 0,
    plaintext_reason TEXT,
    approved_by   TEXT,
    approved_at   TEXT,
    ssh_json      TEXT,
    sentinel_json TEXT,
    cluster_json  TEXT,
    env           TEXT NOT NULL DEFAULT 'dev' CHECK (env IN ('prod','test','dev')),
    protection    TEXT NOT NULL DEFAULT 'confirm'
                  CHECK (protection IN ('readonly','confirm','unrestricted')),
    allow_l4      INTEGER NOT NULL DEFAULT 0,
    tags          TEXT,
    note          TEXT,
    created_by    TEXT NOT NULL,
    created_at    TEXT NOT NULL,
    updated_at    TEXT NOT NULL,
    CHECK (env <> 'prod' OR (protection = 'readonly' AND allow_l4 = 0)),
    CHECK (allow_plaintext = 0 OR (plaintext_reason IS NOT NULL AND length(plaintext_reason) >= 10))
);

CREATE TABLE connection_grant (
    connection_id TEXT NOT NULL REFERENCES connection(id) ON DELETE CASCADE,
    role          TEXT NOT NULL CHECK (role IN ('viewer','operator','admin')),
    granted_by    TEXT NOT NULL,
    granted_at    TEXT NOT NULL,
    PRIMARY KEY (connection_id, role)
);

CREATE TABLE secret (
    id         TEXT PRIMARY KEY,
    kind       TEXT NOT NULL,   -- redis_password/sentinel_password/ssh_password/ssh_key_passphrase/master_wrap
    storage    TEXT NOT NULL,   -- dpapi/dpapi_master/not_stored
    cipher     BLOB,            -- DPAPI 密文（not_stored 时为 NULL）
    entropy    TEXT NOT NULL,   -- redisdesk:v2:credential
    created_at TEXT NOT NULL
);
```

> `CHECK (env <> 'prod' OR ...)` 是数据库层兜底：即使 UI 或程序有漏洞，也无法把生产连接保存成可写。

### 7.3 SecretLease

```python
with SecretLease(profile) as secret:      # memoryview
    pool = build_pool(profile, password=secret)
# 退出：bytearray 清零，引用断开
```

| 约束 | 内容 |
| --- | --- |
| 范围 | 只在 `adapters` 建池函数内打开，覆盖建连过程，不跨请求持有 |
| 类型 | `bytearray`/`memoryview`；禁止 `str` |
| 失败 | 抛 `AppError(E02)`，不含密文或明文片段 |
| 限制 | Python 无法保证 GC 前所有副本被擦除（08 §13 A3） |

### 7.4 配置包导出（P2）

| 项 | 约定 |
| --- | --- |
| 格式 | `redisdesk-config`，版本 2 |
| 加密 | scrypt(N=32768, r=8, p=1, salt=16B) + AES-256-GCM（nonce=12B，tag=16B）；AAD = `格式版本|导出时间|导出账号` |
| 内容 | 连接元数据 + 加密凭据 + 可调参数；**不含审计与命令历史** |
| 口令 | ≥ `export_min_password=12`；连续 5 次错误锁定当前进程 `export_fail_unlock_minutes=15` |
| 明文导出 | **无此路径**（无"包含密码"选项，无 JSON 直出） |
| 导入 | 校验版本/AAD/口令；导入连接强制 `env=prod` + `readonly`，需 Admin 复核后才能修改 |
| 提示 | 红色警告"包内含可解密凭据，禁止放入代码仓库/IM/邮件"；导出事件写审计 |

## 8. 连接级授权与保护档位

### 8.1 保护档位

| 档位 | L1 只读 | L2 写入 | L3 高危 | L4 阻断 | 典型用途 |
| --- | --- | --- | --- | --- | --- |
| `readonly` | 允许 | **拒绝** | **拒绝** | **拒绝** | 生产巡检（prod 强制） |
| `confirm` | 允许 | 确认 | 二次确认 + 输入连接名 | 拒绝（`allow_l4` 且 Admin 才可） | 测试/开发 |
| `unrestricted` | 允许 | 直接执行 | 二次确认 + 输入连接名 | 允许（`allow_l4` + Admin + 理由） | 本地开发 |

补充：

1. `readonly` 同时阻断 `EVAL/EVALSHA/FCALL`、`PUBLISH`、`RESTORE`、`MIGRATE`、`RENAME`、`SET`/`DEL` 等全部写语义命令。
2. 只读档仍允许 `CONFIG GET`、`SLOWLOG GET`、`CLIENT LIST`、`MEMORY USAGE`、`SCAN`、`TYPE`、`TTL`。
3. `prod` 永久 `readonly`；`SHUTDOWN`/`DEBUG`/订阅阻塞命令对所有环境永久阻断（05 §2）。
4. 判定位置：`core/authz.py`（角色/授权）+ `core/policy.py`（风险/档位），**发送前统一执行**；UI 置灰只是提示（08 §3.4 管线）。

### 8.2 角色 → 连接授权

| 规则 | 内容 |
| --- | --- |
| 模型 | `connection_grant`：行存在即该角色可连接 |
| 新建 | 自动授予 `admin`；`operator`/`viewer` 需 Admin 显式授予 |
| 未授权 | **可见但不可连接**：灰色行 + "未授权"徽标 + 提示联系管理员（理由见 08 §3.3） |
| 例外 | Admin 可开启 `hide_unauthorized_connections` 完全隐藏（需审计） |
| 切换连接 | 清空上一连接的临时显示、值缓存、右侧面板；不改变会话解锁状态 |
| 删除 | 级联删除授权行；孤儿行启动清理 |

## 9. Redis 侧最小权限

### 9.1 连接测试自检（`adapters/acl_probe.py`）

建连后（不阻断连接）执行并展示结果：

| 检查 | 命令 | 判定 | 提示 |
| --- | --- | --- | --- |
| 当前账号 | `ACL WHOAMI` | 返回 `default` | **高危**：建议改用专用 ACL 账号 |
| 权限规模 | `ACL GETUSER <whoami>`（无权限则跳过） | 含 `+@all` 或 `~*` | 警告：权限过宽，给出改法 |
| 危险类别 | 同上 | 含 `@dangerous`/`@admin`/`@scripting` | 警告：排查账号不应具备 |
| 写能力 | 同上 | 含 `@write` 且连接为只读档 | 提示：客户端只读保护生效，但服务端仍可写 |
| 版本 | `INFO server` | < 6.0 | 无法使用 ACL 自检与 `SCAN TYPE`，提示降级 |

| 约束 | 内容 |
| --- | --- |
| 不可达 | `ACL GETUSER` 无权限 → 提示"无法检测，请人工核对"，不阻断、不误报（R-39） |
| 结果留痕 | 自检结果写入连接详情（不写审计，属只读诊断）；`default` 账号告警首次出现时写一条 `event=acl_warning` |
| 改法 | 每条警告附"复制修复命令"按钮（只填入控制台，不自动执行） |

### 9.2 三套 ACL 示例（可直接执行）

> 占位符：`<32位随机强口令>` 请用密码管理器生成；`~*` 可按业务改为 `~order:*` 等前缀。
> 执行顺序：先 `ACL SETUSER`，验证能连能读后，再 `ACL SAVE`（写入 `aclfile`，否则重启丢失）。

**① 只读账号（推荐给 Viewer / 生产排查）**

```
ACL SETUSER redisdesk_ro on >'<32位随机强口令>' ~* resetchannels &* \
  -@all +@read +@keyspace +@connection +@transaction \
  -@write -@dangerous -@admin -@scripting -@pubsub -@blocking \
  +info +ping +echo +time +role +dbsize +lastsave \
  +config|get +slowlog|get +slowlog|len \
  +client|list +client|info +client|id +client|getname +client|setname \
  +memory|usage +memory|stats +memory|doctor \
  +cluster|info +cluster|nodes +cluster|slots +cluster|keyslot +cluster|countkeysinslot +cluster|getkeysinslot \
  +object|encoding +object|refcount +object|idletime \
  +scan +type +ttl +pttl +exists
ACL SAVE
```

**② 运维账号（Operator：允许受控写入，禁止高危/脚本/危险类别）**

```
ACL SETUSER redisdesk_rw on >'<32位随机强口令>' ~* resetchannels &* \
  -@all +@read +@write +@keyspace +@connection \
  -@dangerous -@admin -@scripting -@pubsub -@blocking \
  +info +ping +echo +time +role +dbsize \
  +config|get +slowlog|get +client|list +memory|usage \
  +expire +pexpire +persist +del +unlink +rename +copy \
  +cluster|info +cluster|nodes +cluster|slots +cluster|keyslot
ACL SAVE
```

**③ 管理员账号（仅 dev/test；集群运维命令仍建议在堡垒机执行）**

```
ACL SETUSER redisdesk_admin on >'<32位随机强口令>' ~* resetchannels &* \
  -@all +@all -@dangerous \
  +config|get +config|set +config|rewrite \
  +client|list +client|kill +client|no-evict \
  +slowlog|get +slowlog|reset +memory|usage +memory|stats +memory|purge \
  +script|load +script|exists +script|kill +script|flush \
  +cluster|info +cluster|nodes +cluster|slots +cluster|keyslot \
  +save +bgsave +bgrewriteaof +lastsave
ACL SAVE
```

| 说明 | 内容 |
| --- | --- |
| 为什么不给 `+@all` | `@dangerous`/`@admin` 含 `FLUSHALL`/`SHUTDOWN`/`DEBUG`/`KEYS`/`MONITOR`，与服务端最小权限原则冲突 |
| `-@blocking` | 阻断 `BLPOP`/`BRPOP` 等阻塞命令，避免占用连接 |
| `-@pubsub` | 排查工具不需要订阅；如需观察消息，单独建账号并限时使用 |
| 验证 | `ACL WHOAMI`、`ACL GETUSER redisdesk_ro`、`ACL LIST`；用 `redisdesk` 连接后执行 `SET` 应返回 `NOPERM` |
| 落盘 | 必须 `ACL SAVE`；未配置 `aclfile` 时该命令报错，需先在 `redis.conf` 设置 `aclfile /etc/redis/users.acl` |

## 10. 连接测试与状态机

```
[未连接] --测试--> [测试中] --成功--> [已连接(discovering)] --就绪--> [已连接]
                        │                     │
                        ├──失败──> [测试失败]  └──拓扑变化/网络错误──> [重连中] ──> [已连接]
                                                                    └──超过 3 次──> [连接中断]
```

| 步骤 | 命令 | 通过条件 |
| --- | --- | --- |
| 0 会话 | 本地校验 | 已登录且未锁定（否则 E14） |
| 1 授权 | `connection_grant` | 当前角色已被授予该连接（否则 E08 `reason=grant`） |
| 2 可达 | TCP/SSH + TLS 握手 | `connect_timeout_s` 内完成，证书校验通过 |
| 3 认证 | `PING`（`SecretLease` 注入密码） | 返回 `PONG`，无 `NOAUTH/WRONGPASS` |
| 4 版本与能力 | `INFO server` | 解析 `redis_version` → `Capabilities` |
| 5 拓扑确认 | direct：`ROLE`；sentinel：`SENTINEL get-master-addr-by-name`；cluster：`CLUSTER INFO`+`CLUSTER SLOTS` | 槽覆盖 16384（cluster）；主节点（sentinel） |
| 6 ACL 自检 | `ACL WHOAMI`（可选 `ACL GETUSER`） | 不阻断，产出告警 |
| 7 延迟 | `PING` × 3 | 显示平均 RTT（ms） |

测试结果只影响界面状态，**不自动保存配置**；保存时校验 `name` 唯一、必填项与 §7.2 的 CHECK 约束。

| 状态 | 顶栏徽标 | 可用操作 |
| --- | --- | --- |
| 未授权 | 灰点 `未授权` | 无（仅查看详情） |
| 未连接 | 灰点 `未连接` | 编辑、测试、连接 |
| 连接中 | 蓝点 `连接中` | 取消 |
| 已连接 | 绿点 + 环境 + 保护档位 + 角色 | 全部授权页面 |
| 明文连接 | 红点 + `明文` 红徽标 | 同已连接（写命令仍受档位/角色限制） |
| 只读副本 | 黄点 `只读副本` | 写操作被阻断 |
| 连接中断 | 红点 `连接中断` | 重连、查看错误详情 |

## 11. 错误、重试与恢复

| 场景 | 分类 | 重试 | 恢复动作 |
| --- | --- | --- | --- |
| 建连超时/拒绝 | E01 | 是，`connect_retry_times=3`，间隔 1000 ms | 无 |
| TLS 握手/主机名/证书失败 | E01 | 否 | 提示证书问题；不提供忽略选项 |
| 认证失败 | E02 | 否 | 检查用户名/口令/ACL |
| 读超时 | E03 | 否 | 降 `scan_count`、改分页、提高超时 |
| `READONLY`（sentinel 切换） | E04 | 读命令 1 次（重发现后） | 刷新拓扑、提示新 master |
| `CLUSTERDOWN`/槽缺失 | E05 | 刷新槽缓存后 1 次 | 展示缺失槽区间与节点 |
| 隧道/指纹不匹配 | E07 | 否 | 手工核对指纹后重登记 |
| 未授权/角色不足/档位拒绝 | E08 | 否 | 提示需要的角色与授权方式 |
| 审计不可写 | E13 | 否 | 修复存储后重试；期间禁止写命令 |
| 会话锁定 | E14 | 否 | 解锁后回到原页面，不重放命令 |
| DPAPI 解密失败 | E02 | 否 | 要求重新输入口令 |

**禁止**对写命令做任何自动重试：`INCR`、`LPUSH`、`SETNX` 超时后可能已成功，重试会造成重复（R-05）。

## 12. 实现要点清单

| 编号 | 要点 |
| --- | --- |
| C1 | `ConnectionProfile` 不含密码；明文只在 `SecretLease` 内存在 |
| C2 | 所有拓扑共用 `RedisGateway` 接口；UI 不感知节点 |
| C3 | Cluster 逐节点扫描用独立直连客户端（同认证/TLS），槽路由交给 `RedisCluster` |
| C4 | Cluster 多 key 命令按 CRC16 槽分组执行并合并；跨槽事务拒绝 |
| C5 | SSH 只绑 `127.0.0.1`，指纹固定，随会话释放 |
| C6 | 授权（角色+授权表）与风险（档位+L1~L4）在发送前统一判定，快捷键/历史回放同路径 |
| C7 | TLS 默认必需，`verify_hostname` 不可关；明文例外仅 Admin + 理由 + 审计 + 红色标识 |
| C8 | 所有连接异常映射到 E01~E15，UI 不解析原始异常文本 |
| C9 | 生产连接由数据库 CHECK 约束强制 `readonly + allow_l4=0`，不只靠 UI |
| C10 | 连接自检结果只提示不阻断；无 ACL 读权限时降级为"请人工核对" |
