## 1. 一句话定位

RedisDesk 是一个**面向排查而非面向开发**的 Windows 桌面 Redis 客户端：以"安全地看清楚缓存里有什么、快速验证一条命令、顺手拿到排障所需的服务端指标"为核心，把误操作防护做成默认行为而不是可选项。

与通用客户端（RedisInsight、Another Redis Desktop Manager）的差异：

| 维度 | 通用客户端 | RedisDesk |
| --- | --- | --- |
| Key 浏览 | 常见 `KEYS *` 或全量拉取后前端过滤 | 只走 `SCAN` + 游标分页 + 扫描预算，UI 明确显示"已扫描/命中" |
| 危险命令 | 直接透传 | 四级风险模型，L4 默认阻断（`FLUSHALL`/`SHUTDOWN`/`DEBUG`） |
| 生产安全 | 靠人自觉 | `env=prod` 强制只读档；三角色（Viewer/Operator/Admin）+ 连接级授权；写操作审计留痕 |
| 数据保护 | 明文展示、随手复制 | 敏感 key/字段/值默认遮罩，临时显示计时并留痕；导出默认脱敏 |
| 审计 | 无或可改 | 本地审计**哈希链**（SHA-256），启动校验，被改即进入只读应急模式 |
| 定位 | 功能全集 | 聚焦"查看 + 排查 + 轻量运维"，明确不做数据编辑与迁移 |
| 值渲染 | 统一文本/JSON 视图 | 按类型分页渲染，二进制/压缩数据有明确策略，大 key 不自动加载 |

## 2. 目标用户

| 用户 | 典型身份 | 核心诉求 | 使用频率 |
| --- | --- | --- | --- |
| 后端开发 | 业务研发 | 确认缓存 key 是否存在、值结构是否符合预期、TTL 是否被误设 | 每日多次 |
| 值班运维 / SRE | 线上排障 | 快速定位热点 key、查看慢查询与客户端连接、确认内存与淘汰情况 | 故障时高频 |
| DBA / 缓存负责人 | Redis 维护者 | 巡检大 key、核对集群节点状态、执行受控的运维命令 | 每周 |
| 测试 | QA | 造数后核对缓存写入、清理测试环境脏数据 | 每日 |

共同约束：**都在生产或准生产环境边上操作**，因此"防误删、防阻塞、防泄漏"优先级高于"功能齐全"。

## 3. 核心场景

| 编号 | 场景 | 关键动作 | 对应能力 |
| --- | --- | --- | --- |
| S1 | 接口返回旧数据，怀疑缓存没更新 | 按业务前缀找 key → 看 String 值/JSON → 看 TTL 与内存占用 | 04 §5.2、§4 |
| S2 | 缓存命中率骤降 | 抽查同类 key 是否存在、TTL 是否异常、是否被淘汰 | 04 §3.3（过滤）、06 §1.2（命中率） |
| S3 | 某个 Hash 太大拖慢写入 | 找到 key → 看 `HLEN` → 分页抽样 field → 看 `MEMORY USAGE` | 04 §5.3、§6 大 key |
| S4 | 线上突发超时，怀疑慢命令 | 看慢查询日志 → 看客户端列表是否有异常连接 → 看 `INFO commandstats` | 06 §1.3、§2、§3 |
| S5 | 需要执行一条运维命令（如改 TTL、删测试 key） | 控制台输入 → 风险判定 → 确认 → 看结果与耗时 | 05 全篇 |
| S6 | 集群某个节点内存偏高 | 逐 master 浏览 → 节点级 `INFO memory` → 大 key 采样（可选） | 03 §2、04 §3.6、06 §4.4 |
| S7 | 交接班/合规检查 | 导出最近写操作审计（仅 Admin） | 08 §7 |
| S8 | 新人接手，需要能查但不能误删 | 分配 Viewer 账号 + 只授权生产连接 → 只能浏览与只读命令 | 08 §3.2、§3.3 |
| S9 | 排查中发现返回值里有身份证/手机号 | 默认已遮罩 → 需要时临时显示 60 秒 → 审计留痕 | 04 §2.1、08 §6 |
| S10 | 自建 Redis 未开 TLS，业务急着排查 | 走"明文例外"：Admin 填理由 ≥10 字符 → 连接列表红色标识 → 审计 | 03 §3.2、08 §5.2 |
| S11 | 怀疑有人改过审计记录 | 启动自动抽验 → 发现断链 → 只读应急模式 → 按流程恢复 | 08 §7.4 |

## 4. 功能清单与优先级

优先级即交付阶段，阶段定义见 [09](./09-分期计划与待决问题.md) 第 1 节。

### 4.1 连接管理

| 功能 | 优先级 | 说明 |
| --- | --- | --- |
| 直连（TCP + TLS） | P0 | host、port、db、ACL 用户名、密码；`tls_required` 默认开、`tls_version_min=TLSv1.2`、校验主机名 |
| 明文连接例外 | P0 | Admin + 理由 ≥10 字符 + 连接列表红色标识 + 审计（默认无入口） |
| 连接测试与延迟显示 | P0 | `PING` + `INFO server` 拉版本；同时探测 `default` 账号与高危 ACL 并告警 |
| 连接级授权 | P0 | `connection_grant`：某角色可用哪些连接；未授权连接灰色不可连 |
| SSH 隧道 | P1 | 本地端口转发，密钥优先，`host_key_sha256` 固定，无"忽略继续" |
| Sentinel 发现 | P1 | 按 master name 发现主节点，故障转移后自动重发现 |
| Cluster 槽路由 | P1 | `CLUSTER SLOTS/SHARDS`，MOVED/ASK 重定向 |
| 连接分组与搜索 | P2 | 按环境/项目标签过滤，纯本地 |
| 配置包导入导出 | P2 | 口令加密（AES-256-GCM + scrypt），与 dbsync 同规格 |

### 4.2 Key 浏览

| 功能 | 优先级 | 说明 |
| --- | --- | --- |
| `SCAN` 游标分页浏览 | P0 | 默认 `scan_count=1000`，页 500 行 |
| 名称模式匹配（`MATCH`） | P0 | 服务端匹配，不做客户端全量拉取 |
| 类型过滤 | P0（≥6.0）/ P1（降级路径） | 服务端 `SCAN TYPE`；低版本走 pipeline `TYPE` 客户端过滤 |
| TTL / 内存大小过滤 | P2 | 客户端过滤，受扫描预算约束（见 04 §3.3） |
| 虚拟滚动 + 增量渲染 | P0 | 缓冲上限 3000 行，UI 分批 200 行刷新 |
| 集群逐节点浏览 | P1 | 每 master 独立游标，列表带 slot/节点列 |
| 本地索引快照（可选） | P3 | 落 SQLite 供离线搜索，明确"非实时" |

### 4.3 值查看器

| 功能 | 优先级 | 说明 |
| --- | --- | --- |
| String 文本 / JSON 美化 / HEX | P0 | 256KB 内直接加载，超出分块 |
| Hash / List / Set / ZSet 分页表格 | P0 | 禁止 `HGETALL`/`LRANGE 0 -1` |
| ZSet 按 score 排序 | P0 | 正序/倒序/按 score 区间 |
| Stream 条目 + 消费组 | P1 | `XRANGE` 分页、`XINFO GROUPS`、`XPENDING` 摘要 |
| 二进制识别与 HEX 展示 | P0 | 不可打印字符占比 ≥ 30% 判定为二进制 |
| 压缩数据手动解包（gzip/zstd） | P3（待决 Q5） | 默认不自动解压 |
| 大 key 成本提示与分段加载 | P0 | 阈值见 04 §6 |

### 4.4 命令控制台

| 功能 | 优先级 | 说明 |
| --- | --- | --- |
| 单条命令执行 + 多行输入 | P0 | `Ctrl+Enter` 执行，长 value 可换行 |
| 命令历史（本地持久化 1000 条） | P0 | ↑↓ 检索，可搜索、可删除 |
| 风险四级拦截 / 二次确认 | P0 | 见 05 §2、§3 |
| 只读保护开关（连接级） | P0 | 客户端白名单阻断，不依赖服务端 ACL |
| 结果表格（值/耗时/命中） | P0 | 命中/未命中显式标注 |
| 执行取消 | P0 | 协作式取消 + 超时断连兜底 |
| 危险命令解锁（仅 dev/test） | P1 | 需输入连接名确认，审计留痕 |

### 4.5 运维诊断

| 功能 | 优先级 | 说明 |
| --- | --- | --- |
| `INFO` 分节展示与健康判定 | P0（基础）/ P1（全分节） | 内存、连接、命中率、淘汰、复制 |
| TTL 查看与修改 | P0 | `TTL/PTTL` 查看，`EXPIRE/PERSIST` 写操作走确认 |
| Key 删除（单条） | P0 | `UNLINK` 优先，`DEL` 兜底 |
| 慢查询日志 | P1 | `SLOWLOG GET 128`，展示 50 条 |
| 客户端列表 + KILL | P1 | `CLIENT LIST`，KILL 为 L3 |
| 内存分析（`MEMORY STATS/DOCTOR/USAGE`） | P2 | 批量采样估算 |
| 批量按模式删除 | P2 | 二次确认 + 限流 + 总量上限 10000 |
| 大 key 扫描 | P3（待决 Q8） | 采样估算，成本明确告知 |

### 4.6 审计与设置

| 功能 | 优先级 | 说明 |
| --- | --- | --- |
| 写命令与危险命令审计 | P0 | 本地 SQLite，哈希链（SHA-256），保留 180 天，写失败拒绝执行（fail-closed） |
| 审计查询与导出 | P2 | 按时间/连接/风险等级过滤；导出仅 Admin，默认脱敏 |
| 审计完整性校验 | P0 | 启动抽验最近 500 条；断链进入只读应急模式 |
| 敏感值遮罩与临时显示 | P0 | 内置规则；临时显示 60 秒、计审计 |
| 会话锁定 | P0 | 空闲 10 分钟锁定 + Windows 锁屏联动；绝对 8 小时重登 |
| 主题切换（浅色/深色/跟随系统） | P0 | 复用 dbsync token 方案 |
| 默认参数可视化调整 | P2 | 仅暴露附件 A 中标注"可调"的项；安全参数仅 Admin |

### 4.7 身份与账号（v2.0 新增）

| 功能 | 优先级 | 说明 |
| --- | --- | --- |
| 首次启动初始化 | P0 | 无默认账号；强制创建管理员，展示一次 24 位恢复码（只存哈希） |
| 本地登录/解锁 | P0 | 口令 scrypt(N=32768, r=8, p=1)；失败 5 次锁 15 分钟，24 小时累计 10 次锁 60 分钟 |
| 三角色 | P0 | Viewer / Operator / Admin，能力矩阵见 08 §3.2 |
| 账号管理 | P0 | 仅 Admin 可建号、改角色、重置口令、解锁 |
| 恢复码重置 | P0 | 忘记密码时用恢复码重设管理员口令，事件入审计 |
| SSO / 域账号 | 不做（仅扩展点） | `IdentityProvider` 接口预留，本期不实现（08 §3.1） |

## 5. 明确不做（非目标）

| 不做 | 理由 |
| --- | --- |
| 值编辑器（修改 String/Hash 并写回） | 写回语义复杂（并发覆盖、类型冲突），与"排查工具"定位冲突，且极易造成生产数据事故；只保留命令控制台作为唯一写入口 |
| 数据迁移 / 同步 / 导入导出 key | 已有 dbsync 承担同类职责，本工具不重复建设 |
| 监控大盘、指标采集、告警 | 需要常驻采集与服务端，违背"单机桌面工具"形态 |
| 订阅/发布消息客户端、`MONITOR` 长连接 | 阻塞型连接会占用工作线程并放大服务端压力 |
| RDB/AOF 解析、离线数据浏览 | 解析器成本高，使用频次低 |
| 云端同步 / 跨机共享会话 | 单机工具；账号、授权、审计均只在本机 SQLite 生效，不做多端同步 |
| SSO / 域账号 / MFA | 本期只做本地账号；企业统一身份预留 `IdentityProvider` 扩展点（08 §3.1） |
| 作为 Redis 网关、代理或堡垒机 | 本工具是客户端直连；**不能替代网络隔离、安全组、Redis ACL 与服务端审计**（边界声明见 08 §1） |
| Linux/macOS 客户端 | 与用户现有工具链（dbsync）保持 Windows 一致；DPAPI 也仅 Windows 可用 |
| Cluster 运维操作（reshard、failover、节点增删） | 属专业集群运维，误操作代价不可控 |
| 自定义插件 / 脚本市场 | 扩大攻击面，无明确需求 |

## 6. 产品约束

| 约束 | 内容 |
| --- | --- |
| 平台 | Windows 10/11 x64；单文件分发（Nuitka standalone 目录 + 快捷方式） |
| 网络 | 允许直连内网 Redis；不强制联网，无遥测、无自动更新检查 |
| 数据落盘 | 仅本地：`%LOCALAPPDATA%\RedisDesk\`（`redisdesk.db`、`logs\`、`ui-settings.json`） |
| 凭据 | 三种模式：DPAPI（默认）/ DPAPI + 主密码 / 不落盘；任何导出物不含明文 |
| 传输安全 | 默认强制 TLS（≥ TLSv1.2，校验证书与主机名）；明文需 Admin 例外 + 理由 + 红色标识 + 审计 |
| 身份与权限 | 本地三角色 + 连接级授权；无默认账号；首次启动创建管理员并展示恢复码 |
| 审计 | 本地哈希链，保留 180 天、上限 20 万行；审计不可写时拒绝写命令（fail-closed） |
| 安装完整性 | 安装包与更新包必须签名（Authenticode + RSA-3072-PSS-SHA256）；未签名或降级一律拒绝 |
| 规模 | 100 万 key 实例浏览不卡顿；1000 万 key 允许"慢但可见进度、可取消" |
| 服务端版本 | Redis 5.0 起支持；6.0+ 获得类型过滤等增强；7.x 为推荐基线（`HELLO`、`XINFO` 字段差异需兼容） |
| 依赖最小化 | 仅 PySide6、redis-py、paramiko、cryptography；不引入 pandas/numpy 等重型依赖 |

## 7. 成功判定

P0 交付后应满足：

1. 100 万 key 实例上，输入 key 前缀到看到首屏结果 ≤ 3 秒；全程无 `KEYS` 调用（可用 `CLIENT LIST`/`commandstats` 反证）。
2. 在只读档连接上尝试 `SET`、`DEL`、`EVAL` 均被阻断，且审计表出现 `deny` 记录。
3. 打开 500 万元素的 Hash 不触发 `HGETALL`，内存峰值 < 200 MB。
4. 控制台执行 `FLUSHALL` 在 prod 连接被拒绝且无法通过任何 UI 操作解锁。
5. 断网/超时场景下 UI 不冻结，5 秒内出现可读错误提示。
6. 未登录或会话锁定状态下，任何页面都无法发起 Redis 请求。
7. `viewer` 无法执行写命令、`operator` 无法执行 L4、`admin` 在 prod 连接上也无法 `FLUSHALL`——三层都验证过。
8. 手工改一行审计记录后重启，应用检测到哈希链断裂并进入只读应急模式。
9. 返回 `token:*` 类敏感值时默认遮罩；临时显示 60 秒后自动回遮罩并留痕。
10. 未开 TLS 的 Redis 默认连不上；走明文例外后连接卡片显示红色标识。
