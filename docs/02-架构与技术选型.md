## 1. 技术栈

| 项 | 选型 | 版本 | 理由 |
| --- | --- | --- | --- |
| 语言 | Python | ≥ 3.11 | 与 dbsync 一致；`tomllib`、`ExceptionGroup`、更好的类型标注 |
| UI | PySide6（Essentials） | `6.8.2.1` | 与 dbsync 锁定同一版本，避免 Qt 行为差异；仅用 QtWidgets，不引入 QML |
| Redis 客户端 | redis-py | `5.2.1` | 原生支持 Sentinel/Cluster、连接池、`SCAN` 游标、`MOVED/ASK`；不手写 RESP 协议 |
| SSH | paramiko | `3.5.1` | 成熟的本机端口转发与 known_hosts 校验 |
| 加密 | cryptography | `>= 42.0` | 口令哈希（scrypt）、主密码包裹与配置包导出（AES-256-GCM）、审计哈希链（SHA-256）；单机凭据根密钥仍用系统 DPAPI，不引入外部密钥服务 |
| 系统集成 | ctypes（stdlib） | 内置 | 调用 `CryptProtectData/CryptUnprotectData`、`WTSRegisterSessionNotification`（锁屏联动）、命名互斥量 |
| 打包 | Nuitka | `2.4.x` | 与 dbsync 构建链一致，PySide6 插件支持成熟 |
| 本地存储 | SQLite（stdlib `sqlite3`） | 内置 | 单文件、零部署；WAL 模式；不引入 ORM |
| 测试 | pytest | `>= 7.0` | 与 dbsync 一致 |

不允许引入的依赖：pandas / numpy（体积与启动时间）、任何 Web 框架、任何自动更新框架、任何遥测 SDK。

依赖规则（编码时用 import 检查兜底）：

| 规则 | 内容 |
| --- | --- |
| R1 | `core/` 不得 import `adapters/`、`infra/`、`app/`、PySide6 |
| R2 | `adapters/` 可 import `core/`、`infra/`（仅 crypto/日志），不得 import `app/` |
| R3 | `app/services/` 可 import `core/`、`adapters/`、`infra/`，不得 import 具体 Qt 控件 |
| R4 | `app/ui/` 只 import `app/services/` 的 DTO 与信号，不直接持有 redis 客户端 |
| R5 | 任何层都不得 `import` dbsync；复用方式是**复制** `theme.py` / `widgets.py` 的设计与实现，不建立跨工程依赖 |
| R6 | `app/ui/` 不得直接调用 `adapters/` 或 `worker/`；命令执行只能经 `services` 门面，保证授权/审计不被绕过 |
| R7 | 角色/风险判定只允许出现在 `core/authz.py`、`core/policy.py`，其它模块只能调用，不得内联 `if role == ...` 的分支 |

## 5. Redis 抽象层（`adapters/gateway.py`）

统一接口隔离"单机 / 哨兵 / 集群"三种语义差异，上层服务不感知节点。

```python
class Capabilities(NamedTuple):
    supports_scan_type: bool      # Redis >= 6.0
    supports_unlink: bool         # >= 4.0
    supports_memory: bool         # >= 4.0
    supports_stream: bool         # >= 5.0
    supports_cluster: bool
    supports_select_db: bool      # cluster 为 False
    server_version: str

class RedisGateway(Protocol):
    capabilities: Capabilities

    def ping(self) -> float: ...
    def info(self, section: str | None = None) -> dict[str, str]: ...
    def scan(self, node_id: str | None, cursor: int, *, match: str | None,
             count: int, key_type: str | None) -> tuple[int, list[bytes], str | None]: ...
    def execute(self, argv: list[str], *, timeout_s: float) -> Any: ...
    def pipeline(self, commands: list[list[str]], *, batch: int) -> list[Any]: ...
    def route(self, keys: list[bytes]) -> dict[str, list[bytes]]: ...   # 跨槽分组
    def nodes(self) -> list[NodeInfo]: ...
    def close(self) -> None: ...
```

实现分工：

| 实现 | 职责 | 差异点 |
| --- | --- | --- |
| `DirectGateway` | 单机 `redis.Redis` + `ConnectionPool` | 支持 `SELECT db`；无重定向 |
| `SentinelGateway` | `redis.Sentinel` → `master_for(master_name)` | 每次取连接前可校验 `ROLE master`；故障转移后重建池 |
| `ClusterGateway` | `redis.RedisCluster` | 不支持 `SELECT`；多 key 命令需同槽；`scan` 必须指定 `node_id` |
| `TopologyResolver` | 根据 profile 选择实现并注入 transport | SSH 隧道先起本地端口，再把 endpoint 改写为 `127.0.0.1:<local_port>` |

`Capabilities` 驱动降级，禁止在业务代码里写 `if topology == "cluster"` 之外的分支判断：

- 类型过滤：`supports_scan_type` 为真 → 服务端 `SCAN TYPE`；否则客户端 pipeline `TYPE` 过滤（成本计入扫描预算）。
- 删除：`supports_unlink` 为真 → `UNLINK`，否则 `DEL`。
- Cluster 的 `scan`：调用方必须按 `nodes()` 逐个建游标；`DirectGateway.scan(None, ...)` 忽略 `node_id`。

## 6. 线程模型（UI 永不阻塞）

| 线程 | 数量 | 职责 | 约束 |
| --- | --- | --- | --- |
| UI 主线程 | 1 | 渲染、事件、对话框 | **禁止**任何 gateway/store 阻塞调用；单次事件处理 < 16 ms |
| `ConnectionWorker` | 每活跃连接 1 条 QThread | 控制台命令、TTL 读写、单 key 删除、值分页读取、诊断刷新 | 队列 FIFO；同一时刻只允许 1 条命令在飞；命令超时/取消时断连重建 |
| `ScanTask` | 每扫描会话 1 条（`QThreadPool`，最大并发 2） | 游标推进 + 元数据 pipeline | 协作式取消；结果按批 emit |
| `DiagTask` | `QThreadPool(maxThreadCount=4)` | `INFO`/`SLOWLOG`/`CLIENT LIST` 等短任务 | 任务级超时 10 s，重入保护 |

规则：

1. 每个线程自建连接池，**不共享** redis-py 客户端实例：主 worker `max_connections=4`（命令 1 + 值读取 1 + 预留 2），扫描线程单独 `max_connections=2`。
2. 所有连接设置 `health_check_interval=30`、`socket_connect_timeout=5`、`socket_timeout=5`（控制台单条命令可临时覆盖为 `console_timeout_s=10`）。
3. **禁止自动重试写命令**：redis-py 的 `Retry` 只允许用于读命令且最多 1 次；连接建立失败可重试 3 次（间隔 1000 ms）。写命令失败一律返回给用户手工确认，避免 `INCR`/`LPUSH` 重复执行。
4. UI 更新通过 signal 发送 DTO，批量大小 `ui_emit_batch_rows=200`；扫描结果先进入环形缓冲（`scan_buffer_max_rows=3000`），表格用虚拟滚动按需渲染。
5. 关闭连接/窗口时按"取消扫描 → 等待 worker 队列清空（最多 2 s）→ 关闭池"顺序释放，避免线程泄漏。

### 6.1 取消机制

| 场景 | 机制 | 兜底 |
| --- | --- | --- |
| 扫描中取消 | `CancellationToken`（`threading.Event`）在每批 `SCAN` 与每 100 条元数据处检查 | 保留已扫描结果，标记 `cancelled` |
| 值查看器长命令 | 同上，每页检查 | `socket_timeout_s` 触发读超时 |
| 控制台命令 | 取消按钮 → `connection.disconnect()` 强制断 socket，worker 重建池 | 服务端可能仍执行完（已在审计记录"取消"） |
| 恢复扫描 | 从持久化的 `cursors` 继续；已取消的扫描不自动续跑 | 用户显式点击"继续" |

## 7. 错误分类（`core/errors.py`）

| 代号 | 名称 | 典型触发 | 用户提示要点 | 处理 |
| --- | --- | --- | --- | --- |
| E01 | 连接失败 | DNS 失败、连接被拒、网络不可达 | 显示目标 host:port 与耗时 | 可重试 3 次（仅建连） |
| E02 | 认证失败 | `NOAUTH`、`WRONGPASS`、ACL 无权限 | 区分"密码错误"与"ACL 命令被拒" | 不自动重试；提示检查用户名/ACL |
| E03 | 读超时 | 慢命令、网络抖动 | 显示已等待秒数与命令名 | 中断并提示"可提高超时或改用分页" |
| E04 | 服务端错误 | `WRONGTYPE`、`OOM command not allowed`、`READONLY You can't write` | 原样保留 Redis 错误前缀 | 不做隐式修正；`READONLY` 提示主从角色 |
| E05 | 集群异常 | `CLUSTERDOWN`、`MOVED` 循环、槽无主 | 显示节点与槽号 | 刷新槽缓存后最多再试 1 次 |
| E06 | 哨兵发现失败 | master name 不存在、全部哨兵不可达 | 列出尝试过的哨兵 | 不缓存失败结果，下次重试 |
| E07 | SSH 隧道失败 | 认证失败、host key 不匹配、本地端口占用 | 区分三类原因 | 关闭半开隧道，release 本地端口 |
| E08 | 策略拒绝 | 角色不足、连接未授权、只读档、L4 阻断、写保护 | 说明"哪条规则（role/grant/protection/risk）、如何合法执行" | 记录审计 `deny` |
| E09 | 用户取消 | 主动取消 | 无错误弹窗，状态栏提示 | 保留部分结果 |
| E10 | 解码失败 | 非 UTF-8 字节、JSON 非法 | 自动转 HEX 视图 | 不抛异常到 UI |
| E11 | 本地存储失败 | SQLite 只读/磁盘满 | 提示数据可能未保存；写命令被拒绝（fail-closed） | 写操作返回失败，不静默吞掉 |
| E12 | 环境缺失 | DPAPI 不可用、VC 运行库缺失 | 给出安装/替代方案 | 启动期检查并提示 |
| E13 | 审计不可写 | 审计链写入失败、库损坏 | "审计不可写，已拒绝执行写命令" | 阻止 L2~L4 与建连；只读浏览降级可用 |
| E14 | 未认证/已锁定 | 会话过期、空闲锁定、绝对时长达上限 | 弹出解锁/登录，不透露具体账号是否存在 | 解锁后回到原页面，不自动重放原命令 |
| E15 | 完整性校验失败 | 审计链断链、安装包签名无效 | 显示异常序号/文件与取证入口 | 断链 fail-closed；安装拒绝 |

错误对象统一为 `AppError(code, message, hint, retryable)`；UI 只消费这三段文本，不解析异常字符串。

## 11. 安全架构（认证 / 授权 / 凭据租约 / 审计链）

### 11.1 认证与会话

```
启动 → 单实例互斥 → 目录 ACL 自检 → 打开 Store → 审计链末条校验
     → 有无 Admin？ 无 → 首次启动向导（建 Admin + 展示一次性恢复码）
                   有 → 登录页（用户名 + 口令）
     → 会话建立（SessionContext，内存）→ 主窗口
     → 空闲计时器（session_idle_lock_minutes）→ 到时锁定遮罩 → 重新认证
     → WTS 锁屏事件 → 立即锁定
```

| 规则 | 内容 |
| --- | --- |
| 口令校验 | `AuthService.login()`：查用户 → 检查禁用/锁定 → scrypt 校验（常量时间）→ 成功重置失败计数、更新 `last_login_at`、写审计 `auth_login` |
| 失败处理 | 统一提示"用户名或口令错误"；第 4 次起每次延迟 1 s；达阈值锁定并写 `auth_lockout` |
| 会话不落盘 | 无 token 文件、无"记住我"；进程退出即失效 |
| 锁定时 | 清空 UI 中的明文/遮罩状态、清空 `SecretLease` 池、取消进行中的值加载（扫描可暂停保留） |
| 解锁后 | 回到锁定前页面；**不自动重放**任何未完成的命令；敏感值一律回到遮罩态 |

### 11.2 授权单一入口


| 约束 | 内容 |
| --- | --- |
| 唯一实现 | 只有 `core/authz.py` 允许读角色与授权表；`app/ui` 仅消费 `AuthzDecision` 用于置灰与提示 |

### 11.3 凭据租约（SecretLease）

```python
with SecretLease(secret_ref) as secret:      # secret: memoryview[bytes]
    pool = build_pool(..., password=secret)
# 退出：bytearray 清零；引用断开；不进入任何 __repr__
```

| 约束 | 内容 |
| --- | --- |
| 类型 | 只允许 `bytearray` / `memoryview` 承载明文；禁止 `str`（不可变，无法清零且易被日志拼接） |
| 范围 | 租约只在 `adapters` 建池函数内打开，生命周期覆盖建连，不跨请求持有 |
| 失败 | 解密失败抛出 `AppError(E02)`，不带密文与明文片段 |
| 限制 | Python 无法保证 GC 前的副本全部擦除，只能缩短窗口（见 08 §13 A3） |

### 11.4 审计管线（fail-closed）

```
命令/动作 → 授权 → 风险 → [需要审计?]
   ├ 否（L1）→ 执行
   └ 是 → begin tx: 取 chain_state → 计算 prev_hash → INSERT audit_log(pending) → UPDATE chain_state
           ├ 失败 → 回滚 → 拒绝执行（E13），UI 红色提示
           └ 成功 → 执行 → 追加 event=command_result 记录（引用原 seq）
                     ├ 失败 → 状态栏红色常驻 + 阻止后续写命令 + 日志留痕
                     └ 成功 → 正常
```

| 约束 | 内容 |
| --- | --- |
| 只追加 | 命令结果不 UPDATE 原记录，改为追加 `command_result` 记录，链保持纯追加可校验 |
| 单写者 | 单实例互斥量 + 单事务串行；`prev_hash` 必须等于 `chain_state.last_hash`，否则拒绝写入 |
| 断链 | 启动抽验失败 → 只读降级 + 禁止写命令（见 08 §7.4） |
| 性能 | 每次写命令多 2 次 SQLite 事务（< 5 ms，WAL）；不引入网络依赖 |

### 11.5 敏感遮罩管线

```
取到原始字节 → codec 解码(文本/HEX) → SensitiveMatcher(connection, key, field, value)
  ├ 未命中 → 正常渲染
  └ 命中 → 按 action 遮罩(mask_full/mask_partial/hash) → ValueItem.masked=True
              → "临时显示"（Operator+）→ 60 s 计时 → 自动回遮罩 + 审计 reveal_sensitive
```

| 约束 | 内容 |
| --- | --- |
| 遮罩在服务层 | `value_service` 返回前完成，UI 拿不到未遮罩内容（减少误渲染与误复制） |
| 导出 | 默认使用遮罩后的 `ValuePage`；未脱敏导出走独立接口 `export_unmasked`，需 Admin + 二次认证 |
| 匹配器 | 规则编译缓存；单次值匹配耗时上限 5 ms，超时按"命中"处理（保守） |
